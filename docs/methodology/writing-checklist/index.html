写作 Checklist

适用于技术文章、思考随笔、项目复盘和源码阅读笔记的一份写作 checklist。

写作 Checklist

适用场景：技术文章、思考随笔、项目复盘、源码阅读笔记。

动笔前

  • 我这篇文章最想表达的一句话是什么？
  • 这篇文章到底在回答什么问题？
  • 读者看完之后，应该记住哪个判断，而不是哪个细节？
  • 这篇文章的重心是观点、经验、方法，还是信息整理？
  • 如果一句话说不清主题，先不要急着写正文。

结构检查

  • 开头有没有交代“为什么值得讨论”？
  • 第一屏里有没有出现核心观点？
  • 每个小节是否只承载一个中心意思？
  • 小节标题是否比正文更像“判断”，而不只是“标签”？
  • 段落顺序是否符合“问题 -> 判断 -> 论证 -> 例子 -> 收束”？
  • 有没有一段里同时讲了两个以上重点？

表达检查

  • 有没有一句话太长，读一遍很难顺下来？
  • 抽象概念连续出现时，是否补了具体例子？
  • 能不能把“复杂但正确”改成“简单也正确”？
  • 有没有使用模糊词但没有解释，比如“很多”“本质上”“关键”“高质量”？
  • 重要判断是否写得足够直接，不绕弯子？
  • 每一段的第一句能不能单独成立？

风格检查

  • 有没有保留自己的判断力，而不是写成泛泛的正确废话？
  • 有没有为了显得深刻，堆太多抽象词？
  • 有没有把脑子里的推演过程原样倒出来，导致读者跟不上？
  • 语气是不是像在和人交流，而不是在写会议纪要？
  • 有锋芒的地方，是否也给出了论证支撑？

技术文章专项

  • 有没有说明这件事为什么在今天值得讨论？
  • 有没有先交代全局地图，再进入局部细节？
  • 有没有突出关键路径，而不是平均分配篇幅？
  • 有没有讲清楚 trade-off，而不只是描述实现？
  • 有没有说明这个经验可以迁移到什么别的问题上？

收尾检查

  • 结尾有没有回到开头提出的问题？
  • 最后一段是在重复前文，还是在收束并拔高？
  • 有没有一句适合作为摘要或分享文案的总结句？
  • 这篇文章删掉 20% 内容后，会不会更清楚？

复盘问题

  • 哪一段最像“我自己懂，但读者未必懂”？
  • 哪一段最有力量，为什么？
  • 哪一段最空，删掉会不会更好？
  • 如果一周后重写这篇，我最想重写哪一节？
